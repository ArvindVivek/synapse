Create the database schema following the architecture from RESEARCH.md.

**Migration 1 (20260128000001_schema.sql):**
Create these tables with proper relationships:

1. `teams` - id (UUID PK), grid_id (VARCHAR UNIQUE), name, short_name, region, created_at, updated_at
2. `players` - id (UUID PK), grid_id (VARCHAR UNIQUE), name, team_id (FK teams), primary_role (top|jungle|mid|adc|support), created_at, updated_at
3. `tournaments` - id (UUID PK), grid_id (VARCHAR UNIQUE), title, region, start_date, end_date, created_at
4. `series` - id (UUID PK), grid_id (VARCHAR UNIQUE), tournament_id (FK tournaments), blue_team_id (FK teams), red_team_id (FK teams), winner_team_id (FK teams NULL), patch_version, started_at, finished_at, created_at
5. `games` - id (UUID PK), grid_id (VARCHAR UNIQUE), series_id (FK series), game_number, blue_team_won (BOOLEAN), duration_seconds, created_at
6. `drafts` - id (UUID PK), game_id (FK games UNIQUE), blue_bans (TEXT[]), red_bans (TEXT[]), created_at
7. `champion_picks` - id (UUID PK), draft_id (FK drafts), player_id (FK players), team_side (blue|red), champion_name, role (top|jungle|mid|adc|support), role_confidence (DECIMAL), pick_order (1-10), created_at
8. `champions` - name (VARCHAR PK), grid_name, riot_id, aliases (TEXT[]), primary_roles (TEXT[]), created_at
9. `champion_stats` - id (UUID PK), champion_name (FK champions), patch_version, role, games_played, wins, raw_win_rate, smoothed_win_rate, confidence (high|medium|low|insufficient), pick_rate, ban_rate, created_at, updated_at, UNIQUE(champion_name, patch_version, role)
10. `etl_checkpoints` - id (UUID PK), job_type, entity_id, status (pending|in_progress|completed|failed), progress (JSONB), error_message, started_at, completed_at, updated_at, UNIQUE(job_type, entity_id)

Use gen_random_uuid() for UUIDs. Add appropriate constraints (NOT NULL, CHECK for enums). Use TIMESTAMPTZ for all timestamps.

**Migration 2 (20260128000002_indexes.sql):**
Create performance indexes:
- idx_picks_champion_role_patch ON champion_picks(champion_name, role) - most common query pattern
- idx_picks_player_champion ON champion_picks(player_id, champion_name) - player pools
- idx_games_series ON games(series_id) - series lookups
- idx_series_tournament ON series(tournament_id) - tournament rollups
- idx_series_patch ON series(patch_version) - patch filtering
- idx_stats_champion_patch_role ON champion_stats(champion_name, patch_version, role) - stats queries
- idx_checkpoints_status ON etl_checkpoints(job_type, status) - pending job queries

**Types file (types.ts):**
Create TypeScript types matching the schema:
- Database types for each table (TeamRow, PlayerRow, etc.)
- Enums: Role ('top' | 'jungle' | 'mid' | 'adc' | 'support'), TeamSide ('blue' | 'red'), Confidence ('high' | 'medium' | 'low' | 'insufficient')
- Insert types (without id, created_at)

  <action>
Create the GRID API client following Pattern 1 from RESEARCH.md.

**grid-client.ts:**
```typescript
// Use bottleneck for rate limiting (180 req/min overall, 6 req/min per series)
// Use p-retry for exponential backoff on failures
// Handle 429 Too Many Requests with Retry-After header parsing
```

Implement:
1. `GridAPIClient` class with constructor taking apiKey
2. Bottleneck limiter: maxConcurrent=3, minTime=333ms (3 req/sec), reservoir=180, reservoirRefreshInterval=60000ms
3. `query<T>(query: string, variables: Record<string, unknown>): Promise<T>` method that:
   - Wraps fetch in limiter.schedule()
   - Wraps scheduled fetch in pRetry() with 5 retries, factor=2, minTimeout=1000, maxTimeout=30000
   - Sends POST to https://api-op.grid.gg/central-data/graphql
   - Sets headers: x-api-key, Content-Type: application/json
   - On 429: throws error with parsed Retry-After delay
   - Returns parsed JSON response

4. Zod schemas for validating GRID responses (TournamentResponse, SeriesStateResponse)

**queries.ts:**
Define GraphQL query strings:
- GET_TOURNAMENTS_QUERY - fetch tournaments for LoL with date filter
- GET_SERIES_FOR_TOURNAMENT_QUERY - fetch series in a tournament
- GET_SERIES_STATE_QUERY - fetch picks/bans/players for a series

Use the exact query structures from RESEARCH.md code examples.
